# CyCodeIDE

![CyCodeIDE](icons/CyCode.png)

Native C++20 IDE using [CyCode Core](https://github.com/MrMybal/CyCode) and the
shared [CyCodeReader editor](https://github.com/MrMybal/CyCodeReader).
**Development snapshot**, extracted from the CyCode 0.2.3 desktop application.
It is not a new installer or application release.

CyCode owns documents, compiler adapters, persistent language backends, semantic
indexes, diagnostics, guarded transactions, native plugins and service contracts.
Reader and the IDE consume its shared native buffer/codec/process/protocol
components. Reader supplies graphical editor source API 1; the IDE owns windows,
project panels, themes, keymaps and their presentation. One Core and one compatible
ImGui/editor instance are used in the target graph. C++ source API 1 is not a
stable binary ABI.

## Build

```sh
python app/scripts/build.py --fetch
```

CMake 3.24+, Python 3.11+, C++20 and Visual Studio 2022 on Windows or a suitable
Linux/macOS toolchain are required. Exact dependency revisions are pinned in
app/core-source.lock.json and app/editor-source.lock.json. Core and Reader are
public; available Git authentication is used if needed for private dependencies.
No credential belongs in source or command examples. For development checkouts:

```sh
python app/scripts/build.py --core-root <CyCode> --editor-root <CyCodeReader> --fetch
```

The production build keeps native tests OFF and never starts the app. The output
is runtime/build/app/Release/CyCodeIDE.exe on Windows or runtime/build/app/CyCodeIDE
on single-configuration platforms. Its internal target is still CyCode.
Core's genuine offline CyDoc HTML reader is generated by default and staged beside
the executable. --without-documentation is an explicit compile-only option.
The canonical facade/manifest and CLI are staged from Core; no second operation
registry, local workspace, user settings or downloaded task data is distributed.

## Validation and release status

See [extraction and validation](Docs/Extraction.md) and Core's
[native integration guide](https://github.com/MrMybal/CyCode/blob/codex/core-intelligence/app/Docs/CoreExtraction.md).
Core and Reader native integrations and the IDE view suite have passed on
Windows, Linux and macOS CI.
The separate IDE runner suite exercises actual views without opening OS windows;
its exact revisions and platform results are recorded in the extraction guide.
Local native execution remains suspended during the existing antivirus investigation.
Production compilation and headless view checks do not establish full desktop,
multi-monitor or installer acceptance.

Before the first CyCodeIDE release, migrate and validate installer/update identity
and distribution layouts. The historical updater is disabled and its old helper
is not built. The IDE product version and launch identity are independent from
the Core runtime. Legacy desktop/release workflows are archived in .github/legacy
and are inactive. The shared GPL-3.0-only license and dependency notices are retained.
